# DECISIONS.md: 重大架構決策紀錄 (Architectural Decisions)

本文件紀錄 Study Pack Compiler 專案的核心決策背景與權衡考量。

---

## 決策一：為什麼堅持「單一 HTML (Single HTML)」且「零外部 CDN」？

### 背景
既有的學習網站或靜態產生器常產出多個關聯檔案（HTML、CSS、JS、字型），甚至需要透過本機 HTTP Server（如 `npx serve` 或 `python -m http.server`）才能開啟，且常依賴外部 CDN 載入字型與套件。

### 決策理由
1. **極致離線與可攜性**：使用者常常在捷運、飛機或網路受限環境下溫習教材。單一 HTML 檔只需存入手機或電腦，點擊即可無痛開啟。
2. **零過期與零毀損風險**：一旦檔案產出，即使 10 年後外部 CDN 倒閉或連線被封鎖，該單檔學習網站依然能完整呈現與作答。
3. **無伺服器相依**：消除 CORS、本機路徑權限與伺服器架設的門檻。

## 決策二：為什麼所有來源輸入都必須先轉譯為 Normalized Study Pack Schema？

### 背景
不同的來源可能包含 Markdown、CSV、TXT、JSON 或未來的 DOCX。若針對每一種來源各自撰寫產生 HTML 的 Renderer，系統將快速演變為 $M \times N$ 的複雜度。

### 決策理由
1. **契約中心化 (Schema-First)**：透過固定資料契約 `study-pack.schema.json`，將「資料解析 (Parser)」與「視覺呈現 (Renderer)」徹底解耦。
2. **單一維護點**：無論來源是 CSV 還是 Markdown，所有的檢查規則、品質驗證、統計演算法與 HTML 打包邏輯只需維護一套。
3. **未來擴展容易**：未來若要增加新來源（例如 PDF 或 Notion 匯出），只需擴充一個對應的 Parser 轉為 Study Pack 物件，所有前端功能自動享有。

## 決策三：為什麼第一階段堅決不導入 AI 自動生成內容？

### 背景
當前 AI 生成流行，很多人傾向於直接讓 LLM 自動出題、摘要章節或補齊題目解析。

### 決策理由
1. **防止幻覺 (Hallucination) 污染教材**：證照考試與專業學習追求「100% 精確事實」。AI 幻覺會導致考生背錯法規或答案。
2. **首要任務是產生器的確定性與穩定性**：第一階段的核心價值在於「正確的資料能夠穩定可靠地編譯為獨立學習網站」。引入不確定的生成模型會模糊問題根源。
3. **架構預留**：未來的 AI 出題模組將被置於 Source 預處理端，經由人工審閱 (Human Review) 核可後才進入正規化流程，不得直接污染正式 Study Pack。

## 決策四：為什麼學習進度 (Progress) 與教材內容 (Content) 必須嚴格分離？

### 背景
如果在單一 HTML 內部將使用者的作答紀錄直接寫回原始碼或綁死在教材資料中，當教材發布新版本時，舊紀錄將無法繼承或直接遺失。

### 決策理由
1. **教材本體保持純淨唯讀**：HTML 檔案中的 `window.__STUDY_PACK__` 為靜態不可變物件。
2. **進度獨立持久化**：使用者的作答次數、錯題狀態、書籤位置皆儲存在瀏覽器的 `localStorage`（以 `study-pack.{packId}.progress` 為命名空間）。
3. **安全備份與跨版本相容**：教材升級時，只要 `packId` 相同，使用者的錯題紀錄得以保留；同時具備 JSON 匯出與還原機制，重設 (Reset) 亦不會損壞教材本體。
