# 第 04 章：純網路銀行、開放銀行與 API 生態系

---

## 先建立本章的理解脈絡


### 這次先回答三個問題

1. 純網路銀行和既有銀行的差別在哪裡？
2. 開放銀行三個階段開放的資料或行為有何不同？
3. 客戶授權和銀行、第三方業者責任如何區分？

### 用這段話串起觀念

- 純網路銀行主要透過網路提供銀行服務；開放銀行則是在客戶同意和安全控管下，讓銀行資料能由合格第三方提供服務使用。
- API 是系統交換資料的介面，並不代表資料可以任意取用；本章要掌握業者角色、同意流程和責任邊界。

##  本章學習導航與核心地圖

金融服務從以分行為主，逐步轉為在不同生活場景中透過數位管道提供。本章重點在純網銀的營運模式、開放銀行的資料授權流程，以及參與者間的責任分工：
1. 純網路銀行（Internet-Only Bank）《商業銀行設立標準》法定規格與董事資格
2. 台灣獲准設立之三家純網銀名單與發起背景
3. 開放銀行（Open Banking）國際三大推動模式比較
4. 開放銀行三大漸進階段之推進路徑與授權機制
5. 開放 API 架構與第三方業者（TSP）之監理與賠償責任歸屬

##  一、純網路銀行（Internet-Only Bank）法定設立規範

純網路銀行是指所有銀行業務皆透過網際網路、行動通訊等電子通路提供之銀行。

### 1. 核心法定要件（金管會《商業銀行設立標準》第 18 條）
- 最低實收資本額：新臺幣 100 億元（發起人應於發起時一次全額認足，與一般商業銀行完全相同！）。
- 實體據點限制：嚴格禁止設立實體營業分行！
  - *考點例外*：但必須設立實體總行以及客服中心/資訊中心以備主管機關檢查與處理客訴爭議。
- 發起人股東結構門檻：
  - 發起人中金融機構（含金控、銀行、保險、證券）持股比率合計應達 40% 以上；
  - 且其中至少應有一家金控或銀行之持股比率達 25% 以上（確保具備主導金融風控與合規能力）。
  - 同時鼓勵電信、電商等非金融科技業者參股，結合跨界生態圈場景。
- 董事專業資格要求：
  - 具備銀行業工作經驗者，不得低於全體董事人數之 三分之一；
  - 具備金融科技、電子商務或電信等專業背景者，亦不得低於全體董事人數之 五分之一。

### 2. 台灣三家取得許可之純網銀（2019/7/30 核准）：
1. 樂天國際商業銀行 (Rakuten Bank)：日本樂天集團與國票金控合資（生態圈為樂天生態圈與電商點數）。
2. 連線商業銀行 (LINE Bank)：LINE Financial 與台北富邦、聯邦、中信、渣打等合資（生態圈為龐大社群與通訊軟體）。
3. 將來商業銀行 (NEXT BANK)：中華電信、兆豐銀行、新光集團、全聯實業等合資（國家隊電信與零售通路生態圈）。

##  二、開放銀行（Open Banking）理念與國際推動模式

開放銀行倡導「金融資料的所有權屬於客戶本人，而非銀行」！客戶有權授權銀行將其個人帳務與交易資訊透過開放 API（Application Programming Interface）分享給可信任的第三方業者（TSP, Third-Party Service Provider）。

### (一) 全球三大推動模式比較（歷屆必考）
1. 法規強制驅動型 (Mandatory / Regulatory-driven)：
   - 代表：英國 (CMA)、歐盟 (PSD2, 第二號支付服務指令)。
   - 作法：由政府立法強制要求大型商業銀行必須開放 API 讓合規第三方業者介接，否則受罰。
2. 市場自由驅動型 (Market-led)：
   - 代表：美國。
   - 作法：政府無專法強制規定，由市場業者（如 Plaid 等聚合器）自發透過螢幕擷取 (Screen Scraping) 或商業談判介接。
3. 原則引導與自律推動型 (Principles-based / Self-regulatory)：
   - 代表：台灣、香港、新加坡。
   - 作法：主管機關（金管會）不強制入法，採由上而下政策指導、鼓勵銀行自願加入，由銀行公會訂定自律規範，財金公司訂定統一開放 API 技術與資安標準。

##  三、開放銀行三大階段推進與授權機制


| 推進階段 | 開放內容 | 需否客戶個人授權同意？ | 生活情境案例 |
| :--- | :--- | :--- | :--- |
| 第一階段<br/>(公開資料查詢) | 各銀行官網原本公開可查之利率、匯率、分行ATM位置、信用卡優惠等共通資料 |  不需個別授權<br/>（本來就是公開資訊） | 使用比價 App，一次比較 30 家銀行今天的美元定存利率最高是哪一家！ |
| 第二階段<br/>(客戶資訊查詢) | 客戶個人金融帳戶資訊（如存款餘額、信用卡帳單消費明細、投資部位） |  必須取得客戶個別數位授權同意！ | 麻布記帳(Moneybook)等記帳 App，讓使用者一次整合查閱名下所有銀行的帳戶餘額與刷卡紀錄！ |
| 第三階段<br/>(交易面資訊) | 直接在第三方 App 上發動金融交易（如帳戶轉帳扣款、繳費、信貸申請撥款） |  極高安全層級授權認證（雙因子）！ | 在旅遊訂票 App 買機票時，直接於該 App 畫面內觸發銀行帳戶直接扣款轉帳完成支付！ |

##  四、開放 API 與 TSP 業者的責任架構

1. 第一線損害賠償責任歸屬：
   - 依金管會及銀行公會規範，銀行與 TSP 簽署合作契約時，若因資料外洩或系統故障造成客戶損失，銀行需先對客戶承擔第一線賠償責任，之後再依合約向可歸責之 TSP 業者求償，保障消費者權益不踢皮球！
2. TSP 業者的嚴格資安把關：
   - 銀行公會訂定《金融機構辦理開放銀行業務自律規範》，要求介接之 TSP 業者必須具備資安防護能力（如 ISO 27001 認證、敏感資料傳輸採 TLS 1.2 以上加密、個資儲存遮蔽處理等）。

##  歷屆常見易錯觀念

>  陷阱 1：純網路銀行的設立資本額
> - 錯誤題目：「因為純網銀沒有實體分行租金負擔，因此法定最低實收資本額大幅放寬為 10 億元。」
> -  正解：錯！純網銀依然是從事收受存款放款之大眾信用機構，最低實收資本額與一般商業銀行完全一致，必須達新臺幣 100 億元！
>
>  陷阱 2：純網銀能否設立實體據點？
> - 錯誤題目：「純網銀嚴禁設立任何實體空間，連總行或客服人員都必須在家遠端辦公。」
> -  正解：錯！純網銀只是「不得設立實體營業分行」，但必須設立實體之總行及客戶服務中心！
>
>  陷阱 3：開放銀行第一階段是否需要客戶同意？
> - 錯誤題目：「開放銀行第一階段『公開資料查詢』因涉及銀行內部商業機密，每次查詢都必須取得個別客戶之身分證字號與生物辨識同意。」
> -  正解：錯！第一階段開放的是利率、匯率等大眾公開資訊，根本不涉及任何個別客戶個資，完全無需客戶授權！第二階段（客戶帳戶個資）才需要客戶授權！
>
>  陷阱 4：台灣開放銀行採歐盟之強制立法模式？
> - 錯誤題目：「台灣推行開放銀行直接制定專法，強制全體商業銀行限期全數介接所有民間記帳 App，否則重罰。」
> -  正解：錯！台灣採自願參與與自律規範模式，由銀行公會自律規範與財金公司 API 標準引導，非強行立法入罪！
